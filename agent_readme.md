### 3. COMPONENT & REPOSITORY ANALYSIS
- **Routing Paradigm:** No server/router — single-command CLI via commander in `src/cli.ts` (`program.argument('<url>')` with flags `--json`, `-o/--out`, `--probe-forms`, `--lighthouse`, `--ai`, `-t/--timeout`). Check dispatch is a sequential registry loop over `CHECKS` array in `src/core/runner.ts:20`.
- **State Management:** Fully stateless per invocation; the `AuditReport` object (defined in `src/core/types.ts`) is the single mutable aggregate threaded through run → AI-enhance → render → save. No persistence layer; reports are only written when `-o <dir>` is passed (`saveReports()` in `src/cli.ts:76`). Scoring state derived purely from `CheckResult[]` via `computeScore()` (`src/core/scoring.ts:3`: pass=weight, warn=weight×0.5, skip excluded).
- **Data Hydration / API Layer:**
  - HTTP fetch: `normalizeUrl()` + `fetchPage()` (`src/core/http.ts`) using global `fetch` with AbortController timeout and redirect-follow → `FetchedPage{status,headers,html,ttfbMs}`.
  - Browser: `launchBrowser()` (`src/core/browser.ts`) dynamic-imports `playwright` and launches headless Chromium; returns `null` on failure → mobile/forms/speed checks self-report `skip`.
  - Target-site interaction: `page.evaluate()` DOM probes in `src/checks/mobile.ts` / `forms.ts` / `speed.ts`; TLS via node `tls.connect` in `src/checks/ssl.ts`; DNS via `node:dns` in `src/checks/dns.ts`.
  - AI layer: `resolveAiConfig()` + `enhanceReport()` (`src/ai/enhance.ts`) POST `{baseUrl}/chat/completions`; env precedence `LIVECHECK_AI_KEY` > `GROQ_API_KEY` > `OPENAI_API_KEY`; base URL default Groq `https://api.groq.com/openai/v1` (model `openai/gpt-oss-120b`) else OpenAI (`gpt-4o-mini`); overrides `LIVECHECK_AI_BASE_URL`/`LIVECHECK_AI_MODEL`. Prompt assembled by `buildPrompt()`/`sortFindings()` (`src/ai/prompt.ts`) with deterministic fail→warn, weight-desc, group-order ordering. `.env` loaded by `loadEnvFile()` (`src/ai/env.ts`) at CLI startup.
- **Primary Functional Flow (`npx livechecks https://site.com --ai -o reports/`):**
  1. `src/cli.ts` runs `loadEnvFile()`, parses flags, calls `runAudit(url, opts)` from `src/core/runner.ts`
  2. `runAudit()` → `normalizeUrl()`, `launchBrowser()`, `safeFetch()` → builds `CheckContext{url,timeoutMs,probeForms,useLighthouse,browser,page}`
  3. Emits `reachabilityResult()`, then iterates `CHECKS` sequentially (dns→ssl→headers→seo→mobile→forms→speed); any thrown check degrades to a `warn` result (`${check.id}-crashed`)
  4. Browser closed in `finally`; `computeScore()` + `summarize()` produce the 0–100 weighted score
  5. If `--ai`: `enhanceReport(report)` attaches `report.aiAnalysis` (failure is non-fatal warning)
  6. If `-o`: `saveReports()` writes `livecheck-<host>-<timestamp>.md` + `.json`; output rendered by `renderTerminal()` or `renderJson()`
  7. Exit code: `0` clean, `1` any FAIL, `2` fatal error

### 4. DEVELOPER AGENT EXECUTION INSTRUCTIONS
- "When modifying code in this project, always adhere to the existing plugin-check pattern: implement new audits as a `Check` object (`id/title/group/requiresBrowser/run(ctx)`) registered in the `CHECKS` array in `D:\Ibrahim106\Desktop\livecheck\src\core\runner.ts`, returning pure `CheckResult[]`; keep checks read-only unless an explicit flag gates mutation (see `--probe-forms`)."
- "Common pitfalls or sensitive modules to avoid breaking:
  - Dynamic imports use literal specifiers (`'playwright'`, `'lighthouse'`, `'chrome-launcher'`) so tsup externalizes them — do not convert to variable specifiers or static imports.
  - `ctx.browser === null` contract: mobile/forms/speed must return `status:'skip'` with the `npx playwright install chromium` hint; CI installs Chromium explicitly.
  - Exit-code contract (0/1/2) is consumed by CI gating — preserve logic in `src/cli.ts`.
  - Version drift: `VERSION = '0.1.0'` in `src/cli.ts:13` vs `0.3.0` in `package.json` — bump both together on release.
  - `tests/smoke.test.ts` hits the real network only when `LIVECHECK_SMOKE=1`; keep it gated.
  - `website/` is an independent Vite/React/Supabase app tracked in the same repo with its own lockfile/configs — never run root lint/typecheck against it or merge its deps into root package.json.
  - `.env` holds live provider keys and is gitignored (verified untracked) — never commit, log, or embed key values; `.env.example` documents the full env contract with placeholders — copy it, never paste real keys into tracked files; README guarantees only check titles/statuses/details are sent to the AI provider."
- "Standard build/test commands to verify changes: `npm run verify` (= `npm run lint && npm run typecheck && npm test && npm run build`); targeted dev run `npm run dev -- https://example.com`; full CI parity requires `npx playwright install chromium` first."
